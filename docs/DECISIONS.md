# DECISIONS

Where the data contradicted the spec, or the spec left a choice open. Newest decisions go at the bottom.
"User" marks choices confirmed by the user before implementation (2026-11-03).

| ID | Decision | Why |
|---|---|---|
| D-001 | Repository layout lives at the repo root (`src/sopverify`, `configs/`, `procedures/`, …), not in a nested `sopverify/` folder. | The repo *is* the project. |
| D-002 | Expected front resolution **1280×720** (confirmed on all 45 video files, 2026-11-03) (`video.expected_resolution`). Uploads with another size get a warning, and the ROI is rescaled proportionally. | ASR metadata of all 45 pool executions says 1280×720. Spec 5.1 said 1280×800. To be re-checked on the videos in notebook 01 §8. |
| D-003 | **Demos (user):** an execution qualifies when all 17 components are installed (ASR state 1) at the end, it has no Remove events, and ≤ 5 % of frames are ANOMALY per hand. Experts are preferred once metadata labels them (`demos.expertise: prefer_expert`). Draws pick distinct participants. | No execution has zero ANOMALY phases (spec's "clean"). Anomaly segments are mostly 1–4 s fumbles. 12 candidates from 8 participants. |
| D-004 | **Graph source `manual` (user).** IMPACT's released graph is not used. | The released `procedure_graph.json` is data-mined, mixes disassembly, and has no install→install edges. |
| D-005 | `psr` step set = the 17 `Install <component>` events. `Incorrectly installed` and `Remove` events are not SOP steps. Event completion is the **last** occurrence of the event. A step is *done at the end* when its components' ASR state at the end is 1 (install) or 0 (remove). Rework = an install later undone by a Remove. | ASR −1 is used transiently during almost every installation, so it cannot mean "failed step" by itself. |
| D-006 | **End-of-video handling.** (a) `labels.adaptive_tail`: when a step completes < 2 × `pos_margin_s` before the end, positives start at completion + min(pos_margin, tail/2), with at least one frame. (b) `smoothing.min_on_end_s = 1.0`: an ON run reaching the end of the video only needs 1 s. (c) The VLM adds a keyframe 0.2 s before the end. | The handle step ends a median 2.4 s before the recording stops. Without these it can never be DONE. |
| D-007 | **`grouped` = 5 steps (user):** rotor, adapter plate, bearing plate, locking lever, handle. Below the spec's 8–15 target. | The annotations resolve about 7 instants. The extra 2 would separate single small screws that are hard to see from the front. `psr` keeps the fine level. |
| D-008 | Truncation cuts are at least `min_gap_s` = 5 s from every GT completion and at least 10 s into the video. An m that cannot be realised is skipped. | Keeps truncated ground truth unambiguous. Steps completing within 5 s of each other cannot be split by a cut. |
| D-009 | **`tas_s` (user):** the 13 TAS-S labels used in reassembly. RETRIEVE_* / STORE_TOOL / FINISH are `visually_verifiable: false, required: false`. Completion = time of the **end frame** of the last segment with the label. A segment still running at t_end is incomplete. | Action labels have no lasting end-state. Using the end frame keeps completions inside the video (E0 found the exclusive end fell after the last frame). |
| D-010 | Frame caches go to local scratch (`video.frame_cache_on_scratch`). Features and traces go on Drive. | Frames are an intermediate and large. The user has < 50 GB of Drive. |
| D-011 | **Selective download (user: limited Drive):** front videos and VideoMAEv2 features are extracted from the remote zips with HTTP range requests (`download.RangeFile` + `zipfile`). Partial downloads are CRC-32 checked per member. Small bundles (annotations, sample) are downloaded whole and SHA256-checked. | The VideoMAEv2 bundle is 21.6 GiB for 5 views, and there is no per-view bundle. |
| D-012 | vLLM is **not** a pyproject extra. Notebook 04 installs it in a fresh runtime. `[vlm]` = qwen-vl-utils + accelerate. Default backend `vllm`, `transformers` as fallback; `auto` tries both. | vLLM pins its own torch and would replace Colab's preinstalled torch in every notebook. The user has an A100. |
| D-013 | The checker looks *through* NOT_VERIFIABLE prerequisites to their own prerequisites, and flags `prereq_not_verifiable`. | The spec doesn't cover NOT_VERIFIABLE prerequisites. Looking through keeps order checks meaningful. |
| D-014 | **GT order violation:** s is done at t_end and, for a prerequisite p, `completion(s) < completion(p)` **or p is not done at t_end**. | Mirrors what the checker can observe ("done without its prerequisite"). Without it, E0 could not be perfect. |
| D-015 | Prototype scorer: `sigmoid(α·(cos_after − cos_before) + β)`, with α, β from a 1-D logistic regression on leave-one-demo-out margins (in-sample when K = 1). | A bias term calibrates where the decision boundary sits. |
| D-016 | A step with no positive demo frames gets a constant score of 0.5, so it becomes UNCERTAIN, never a silent NOT_DONE. | Honest "can't tell". |
| D-017 | Dev/test: participants shuffled (seed 0), dev filled to ≥ 30 % of executions. Result: dev = ER10WE06, KI03AR28, LE06AS03, NA07GE21 (15 executions), test = 30. Each seed's eval set excludes that seed's demos. | Spec 9.2. All four LE06AS03 runs (real non-compliant) fall in dev, so test relies more on truncations. Recorded, not tuned away. |
| D-018 | Tuning on dev: grid over `smoothing.tau_on/tau_off/min_on_s` and `checker.tau_low` (`configs/experiments/_base.yaml`). Objective: meet FA ≤ 1.0 per compliant video and review ≤ 20 % first, then maximise not-done recall, then F1. The VLM verifier is applied after tuning, not inside it. | User-confirmed targets (spec 15 Q4). Verifier calls are too costly per grid point. |
| D-019 | `inferred_demos` uses `min_support = K`. | With K = 2 the default of 5 yields no edges at all. |
| D-020 | Official PSR evaluator: only step F1 and delay are reused (`eval/official.py`). | POS lives inside its `main()`. |
| D-021 | No IMPACT data, frames, features or reports are committed (`.gitignore`). `vocab.yaml` holds only label names. The repo is public. | CC BY-NC-SA 4.0. |
| D-022 | Dependency versions are lower bounds in `pyproject.toml`. Working Colab set (notebook 00, 2026-11-03): Python 3.13.16, torch 2.11.0+cu130, transformers 5.22.0, numpy 2.4.6, scipy 1.16.3, pandas 2.2.3, scikit-learn 1.6.1, pydantic 2.14.1, av 19.0.2, opencv 4.14.0, plotly 5.24.1, gradio 6.31.0, networkx 3.7, huggingface_hub 1.33.0; GPU A100-SXM4-40GB. Pins will be added once the full pipeline has run on this set. | Spec 4.3: use Colab's preinstalled torch. |
| D-023 | Time basis: grid `t_k = k / sample_fps` with `t < duration`. The frame on screen at t is `floor(t·fps)`. Shipped VideoMAEv2 row k ↔ frame k. | One rule everywhere (`video/timegrid.py`). |
| D-024 | Expertise is unknown. The release's only metadata file is `metadata/NASA_TLX_anonymized.xlsx`; the parser reads CSV/JSON/Excel rows that name a participant and "expert"/"novice", and `data.expertise_overrides` holds manual fixes. | Not in the annotations. Notebook 02 §0 shows whether the Excel file has it. |
| D-025 | Evidence keyframe: completion + 3 s if done, else the time of max score, clipped inside the video. | Spec 8.7, extended to not-done steps. |
| D-026 | For a step with ON runs but no final ON run, confidence = 1 − (max smoothed score after the last run). | The spec only defines the "no ON run" case. |
| D-027 | The prototype and kNN scorers compare whole frames. In the synthetic test they cannot see a step done *before* its usual predecessor, because demo "after" frames always include the predecessor. Only the linear probe isolated it. | An expected finding for E3: whole-frame similarity entangles steps that are always done together in demos. |
| D-028 | **User approvals (2026-11-04):** DATA_NOTES reviewed; the 5-step `grouped` set; the manual graphs, with **G5 (handle) requiring only G1** (the manual's "handle last" is not enforced); the `psr` and `tas_s` sets; `sop.md`. The ROI is confirmed separately in notebook 02. | M1 and M2 gates. |
